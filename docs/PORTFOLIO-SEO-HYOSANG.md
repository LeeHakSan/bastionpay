## 1. 프로젝트 한 줄 소개

BastionPay는 모의 오픈뱅킹·가상계좌 웹 서비스에 웹 방어, VLAN/VPN 망 분리, Graylog·Wazuh 관제, n8n 자동 대응을 연결한 교육용 금융 보안 실습 프로젝트입니다.

## 2. 개인 역할과 기여 범위

- 역할: 서기 · pfSense 망 구성
- 담당 시스템: VMware 기반 pfSense VM, WAN·관리망·서비스 VLAN, OpenVPN TAP 연결
- 직접 수행·검증한 범위
  - 관리망 게이트웨이 `10.10.10.1`과 서비스 구간 주소·인터페이스 구성
  - WEB20·DB30·SOC40·TEST60 등 VLAN 접근 정책과 pass/block 로그 확인
  - PC13 VMware NAT·UDP 포워딩·Windows 방화벽·정적 경로 설정
  - PC16 웹 서버의 TCP 443 출발지 제한 규칙 확인
  - Kali → TEST60/DB 구간의 기본 차단 → 임시 허용 → 규칙 원복 검증

웹 애플리케이션, SIEM 룰, n8n 워크플로 자체의 소유자는 README의 팀 구성표에서 별도로 구분합니다. 개인 발표에서는 공통 산출물과 위 네트워크 담당 범위를 섞어 말하지 않습니다.

## 4. 문제 해결 사례

### 문제: 서비스 PC를 VLAN에 연결하면서 실제 통신 경로를 증명해야 함

- 원인: 학원망 주소만으로 접근하면 pfSense 정책을 통과하지 않으므로, 물리망 연결과 VPN 논리 링크를 분리해 검증해야 했습니다.
- 해결: OpenVPN TAP으로 이더넷 프레임을 운반하고, pfSense에서 TAP 브리지와 802.1Q VLAN을 연결했습니다. 출발지·목적지·포트를 제한한 규칙을 만든 뒤 시험 client에서 차단·허용·원복을 순서대로 확인했습니다.
- 결과: `Kali → 10.10.30.50:8080` 경로에서 기본 차단 로그, 임시 허용의 HTTP 200, 규칙 제거 후 재차단 로그를 남겼습니다. 따라서 정책 설정만이 아니라 실제 패킷 경로와 상태 변화를 증거로 제시할 수 있습니다.

## 5. 개선점과 남은 과제

현재 문서에 완료로 표시하지 않은 항목은 다음과 같습니다.

- SOC40 수집 목적지가 이전 PC 주소에 남아 있어 종단 연동을 다시 맞춰야 함
- pfSense 원격 syslog를 Graylog로 보내는 구성이 미완료
- SOAR50 VLAN 미연결 및 n8n의 DB 호스트 배치 재검토 필요
- 관리 LAN의 allow-any 규칙을 최소 권한으로 축소해야 함
- 학원망 직접 접근 경로가 pfSense를 우회하므로 격리 모델을 보완해야 함

이 항목들은 포트폴리오에서 숨기지 않고, `문제 → 원인 → 조치 계획 → 확인 방법` 순서로 설명할 개선 과제로 남깁니다.

## 6. 이력서 프로젝트 항목 초안

**BastionPay — 금융 웹 보안·망 분리·관제 자동화 실습**  
팀 프로젝트 · 2026.10–2026.11 · pfSense/VLAN/VPN 담당

- VMware pfSense 기반 관리망·서비스 VLAN·TEST 구간을 설계하고 OpenVPN TAP 논리 링크와 방화벽 정책을 구성
- 출발지·목적지·포트 기반 최소 허용 규칙을 적용하고 Kali 시험에서 차단→허용→원복 흐름을 로그로 검증
- PC13 NAT/UDP 포워딩, PC16 Windows 443 호스트 방화벽, 관리망 접근 경로를 문서화
- 웹 이벤트가 Graylog·Wazuh 탐지와 n8n 대응으로 이어지는 전체 구조에서 네트워크 경계와 증거 수집 지점을 정리

위 수치와 주소는 실습 환경 기준입니다. 실제 운영 경험이나 외부 성과처럼 확대해 쓰지 않습니다.

## 7. 자기소개서 기본본에 넣을 수 있는 서술 초안

금융 서비스를 모사한 보안 실습 프로젝트에서 pfSense를 중심으로 관리망과 서비스 구간을 분리하고, OpenVPN TAP과 VLAN 정책이 실제 통신 경로에 적용되는지 검증했습니다. 설정 파일만으로 끝내지 않고 Kali 시험에서 기본 차단, 임시 허용, 정책 원복을 수행해 방화벽 로그와 응답 변화를 함께 확인했습니다. 이 과정에서 학원망 직접 접근, 이전된 SOC 주소, 최소권한이 아닌 관리 규칙처럼 설계와 운영 사이의 차이를 발견했고, 남은 위험을 숨기지 않고 재현 절차와 개선 과제로 문서화하는 습관을 갖게 됐습니다.
